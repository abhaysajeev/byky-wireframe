Built on the shared byky-screen.css/js base (see byky-screen-design-system.md and cms_country_state_management.html for the Rent Bill / Direct Bill tab pattern, which mirrors that screen's Countries/States tabs exactly). This is a live rental-transaction feed -- order numbers, customer names, fare/deposit/tax amounts. Nothing in the client's source files supplies real transactions (Customer Details & Registration is itself still awaiting client data), so this module doesn't invent figures on its own initiative (CLAUDE.md 12). RMS WEB APK UI.xlsx feedback: Location -> Branch and Order Status -> Type are label-only renames; Type and Search In both gain a Credit Note option; a From/To Date pair (flatpickr, defaulting to today) sits ahead of Search; and the tab row above the grid gains All (default) and Credit Note alongside Rent Bill/Direct Bill. All/Rent Bill/Direct Bill now show 5 explicitly requested, clearly fabricated demo rows apiece (apps/byky_live/data.py's rent_bill_orders/ direct_bill_orders) instead of the awaiting-data state -- see that module's docstring for why this is a deliberate exception, not a reversal, of the no-invented-money rule. Credit Note keeps the awaiting-data state (its own tiles/columns are a credit-note shape -- Credit Note Number, Amount, Issued By -- not the vehicle/order shape the bill tabs use).
